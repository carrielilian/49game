# 代理游戏财务管理需求文档

> 文档用途：技术开发、接口联调、功能测试与业务验收  
> 文档状态：已确认主规格与当前可运行原型同步
> 基准日期：2026-07-31
> 适用原型：代理游戏财务平台

## 1. 背景与问题

代理游戏财务业务需要统一维护厂商、游戏、合同、结算公式和数据拉取配置，并在同一收入结算页面接入系统拉取与文件导入数据，完成收入、退款、游戏账户汇总、付款申请、实际付款和结算函留档。

当前需求以可运行原型和原型批注为产品基准。本文件将分散在各页面中的字段、交互、计算、快照和异常规则整理为统一口径，供技术开发和测试验收使用。

## 2. 目标

1. 建立厂商、游戏、合同、结算公式和自有渠道之间的基础数据关系。
2. 支持统一收入列表接入系统拉取和文件导入数据，并支持独立的退款拉取与结算。
3. 按游戏汇总结算结果，支持预付分成抵扣和付款申请。
4. 付款申请成功时冻结关键业务数据，保证后续付款与结算函可追溯。
5. 支持付款结果、请款凭证、结算函及收入汇总统计。
6. 为技术开发提供明确的数据口径，为测试提供可执行的验收标准。

## 3. 用户与场景

| 用户角色 | 核心任务 |
|----------|----------|
| 财务人员 | 维护结算公式、导入或拉取收入数据、执行结算、申请付款、登记付款结果、维护凭证 |
| 游戏运营人员 | 维护厂商、游戏、合同、合作内容和自有渠道游戏ID |
| 财务负责人/管理人员 | 查看付款记录、结算函和收入汇总，核对业务结果 |
| 测试人员 | 按字段、流程、状态、计算和异常规则完成验收 |

## 3.1 已确认的渠道与结算总则

| 维度 | 规则 |
|------|------|
| 渠道归属 | 相对当前业务类型分为自有渠道和外部渠道 |
| 数据接入方式 | 系统拉取或文件导入；收入主列表不展示该字段 |
| 公式选择 | 自有渠道取自有渠道公式；所有外部渠道统一取外部渠道公式 |
| 收入页面 | 单页【收入结算】，无页签，拉取与导入共用主列表 |
| 退款页面 | 单页【退款结算】，仅系统拉取 |
| 结算按钮 | 当前查询范围存在未结算记录即可点击 |
| 批处理 | 全量预校验、一次性写入；任一失败则本批全部不结算 |

缺少结算公式时按游戏ID去重提示：`{游戏ID}缺少结算公式`；多个ID使用中文顿号连接。其他失败统一提示：`结算失败，本次数据均未结算：{原因}`。

【数据拉取】抽屉顶部仅显示游戏和厂商，不显示业务类型及平台字段；抽屉仅展示“自有渠道”“外部渠道”两个分组，标题及提示不展示数据接入方式、平台关系或角色信息；文件导入的外部渠道不在抽屉展示。

## 5. 术语与基础口径

| 术语 | 定义 |
|------|------|
| 业务类型 | 游戏盒、快爆；各页面数据按当前业务类型隔离展示 |
| 游戏名称 | 游戏上线后的正式中文名称，对应游戏 `onlineName` |
| 游戏英文名称 | 选填；英文结算函优先使用 |
| 合同游戏名称 | 合同签约使用的名称，可与游戏名称不同 |
| 支付币种 | 合同约定币种，人民币或美金 |
| 付款币种 | 游戏付款设置中的实际付款币种，人民币或美金 |
| 自有渠道 | 当前业务类型自身平台的渠道 |
| 外部渠道 | 当前业务类型在另一平台发行的渠道 |
| 汇总渠道 | 游戏盒或快爆，用于系统拉取收入、退款和统计汇总 |
| 待结算金额 | 结算公式的收入计算基数 |
| 结算收入 | 收入数据按结算公式计算后的结果 |
| 退款金额 | 自有渠道为财务中心原始退款金额；外部渠道为“原始退款金额 × 财务中心结算公式”的结果 |
| 结算退款 | 退款数据按对应规则计算后的结果 |
| 申请付款快照 | 点击“确认申请”成功时冻结的游戏、厂商、预付、付款设置、汇率和金额信息 |
| 结算函快照 | 申请付款成功时冻结的结算函明细、合计、抵扣和初始实际付款金额 |

## 6. 通用体验与内容要求

### 6.1 页面与查询

1. 当前业务类型可切换“游戏盒 / 快爆”；切换后仅展示该业务类型且用户已获业务授权的数据。业务未授权时保留已授权功能入口，页面显示正常空状态。
2. 列表查询条件采用多条件 AND 关系。
3. “游戏ID / 游戏名称”以 `ID / 名称`形式展示。
4. 金额展示使用币种符号和千分位，小数保留两位。
5. 人民币使用 `￥`，美金使用 `$`。
6. 未产生的数据统一显示“-”。
7. 时间精确到秒时使用 `YYYY-MM-DD HH:mm:ss`；月份使用 `YYYY-MM`。

### 6.2 表单反馈

1. 必填项使用必填标识。
2. 字段校验失败时，在字段下方显示红色错误文案。
3. 多字段未完善时，显示红色提示“请完善所有信息”。
4. 保存成功时关闭对应抽屉并显示绿色提示“提交成功”，批注明确要求不关闭的功能除外。
5. 取消或关闭不保存本次未提交修改。

### 6.3 金额输入

1. 合同金额、合同合作内容金额及已付款项金额不得小于0。
2. 金额最多保留小数点后两位。
3. 汇率必须为正数小数，最多保留小数点后四位。

### 6.4 权限设计

#### 6.4.1 权限计算

`可操作数据 = 已授权业务范围 ∩ 已授权功能范围`

1. 业务权限按“游戏盒、快爆”分别授权。
2. 功能权限按“一级权限 → 二级权限 → 三级权限 → 按钮权限”控制。
3. 业务权限决定页面返回哪些业务数据；功能权限决定菜单、页面入口和按钮是否可见、可访问。
4. 查询权限和导出权限跟随列表权限，不设置独立权限点。
5. 前端展示和服务端接口均须执行同一权限校验，不能仅依赖前端隐藏入口。

#### 6.4.2 未授权表现

| 场景 | 页面表现 |
|------|----------|
| 业务未授权 | 已获功能权限的菜单、页面和按钮正常显示；对应业务不返回数据，列表显示正常“暂无数据”空状态 |
| 功能未授权 | 对应菜单、页面入口或按钮直接隐藏，不显示禁用态 |
| URL访问未授权功能页面 | 禁止加载业务内容，统一显示“暂无权限” |
| URL访问已授权功能但业务未授权 | 页面正常打开，但不返回对应业务数据，不显示“暂无权限” |

#### 6.4.3 功能权限树

| 一级权限 | 二级权限 | 三级权限 | 按钮权限 | 备注 |
|----------|----------|----------|----------|------|
| 代理游戏台账 | 游戏支付管理 | 厂商管理 | 列表、添加厂商、编辑 | 查询跟随列表 |
| 代理游戏台账 | 游戏支付管理 | 游戏管理 | 列表、添加游戏、编辑、合同管理、已付款项、操作记录 | 查询、导出跟随列表 |
| 代理游戏台账 | 财务分成管理 | 结算配置管理 | 列表、结算公式、数据拉取、公式记录 | 查询跟随列表 |
| 代理游戏台账 | 财务分成管理 | 收入结算 | 列表、数据导入、数据拉取、结算 | 查询跟随列表 |
| 代理游戏台账 | 财务分成管理 | 退款结算 | 列表、数据拉取、结算 | 查询跟随列表 |
| 代理游戏台账 | 财务分成管理 | 游戏请款管理 | 列表、付款设置、申请付款 | 查询跟随列表 |
| 代理游戏台账 | 财务分成管理 | 游戏付款管理 | 列表、请款凭证、标记付款、结算函信息、结算函下载、详细信息 | 查询跟随列表；结算函查看与下载分别控制 |
| 代理游戏台账 | 数据统计 | 收入汇总统计 | 列表 | 查询、导出跟随列表 |

## 7. 功能要求

## 7.1 厂商管理

### 7.1.1 厂商列表

| 列 | 规则 |
|----|------|
| 厂商ID / 厂商名称 | 单行显示“ID / 名称”；ID由系统生成，名称为签约公司名称 |
| 发票信息 | 展示发票类型，支持列筛选 |
| 操作 | 仅提供“编辑” |

列表规则：

1. 查询栏仅显示“厂商ID / 厂商名称”一个输入框，ID或名称任一包含关键字即可命中。
2. 厂商关键字与发票信息表头筛选使用 AND 关系。
3. 默认按添加时间倒序；新添加厂商置顶，历史记录无添加时间时按厂商ID回退排序。
4. 列表不展示汇总行；查询无结果或业务未授权时保留表头并显示“暂无数据”。
5. 列表权限控制页面和查询；“添加厂商”“编辑”分别受按钮权限控制。

### 7.1.2 添加/编辑厂商

厂商信息字段：

| 字段 | 必填 | 规则 |
|------|------|------|
| 厂商编号 | 否 | 添加时显示“-”；编辑时只读 |
| 厂商名称 | 是 | 公司全称 |
| 联系人 | 否 | 文本 |
| 手机 | 否 | 文本 |
| 邮箱 | 否 | 文本 |
| 单位地址 | 否 | 文本 |
| 发票信息 | 是 | 专票6%、专票3%、专票1%、普通发票、其他 |
| 扣税点 | 条件必填 | 发票信息选择“其他”时显示在第二行、发票信息右侧；0–100，最多两位小数 |

银行信息字段：

| 字段 | 必填 | 布局 |
|------|------|------|
| 开户名称 | 是 | 第一行 |
| 开户银行 | 是 | 第一行，文本输入 |
| 开户银行所在地 | 是 | 第一行，文本输入 |
| 支行名称 | 是 | 第二行 |
| 银行卡号 | 是 | 第二行 |
| 银行代码 | 否 | 第二行 |

业务规则：

1. 厂商基础共有七个必填项：厂商名称、发票信息和五项必填银行信息；发票选择“其他”时，扣税点额外必填。
2. 编辑时不可修改厂商编号和所属业务类型。
3. 修改发票信息后，使用“跟随发票”的结算公式扣税点同步变化。
4. 发票信息为“其他”时，在添加或编辑厂商表单中维护扣税点；结算配置读取该值。
5. 厂商编号按业务类型独立递增：游戏盒从 4001 起，快爆从 8001 起。
6. 当前原型不额外校验联系人、手机号和邮箱格式；银行卡号按文本原值保存，不转换为数字。
7. 单字段缺失时在字段下显示“{字段名}不能为空”；存在任一错误时阻止保存并提示“请完善所有信息”。
8. 取消或关闭不保存；保存成功关闭抽屉并提示“提交成功”。
9. 厂商名称变更后各主列表和查询读取最新名称；历史结算函继续读取申请付款时的快照。
10. 申请付款前只校验开户名称、开户银行、开户银行所在地、支行名称、银行卡号五项银行信息；银行代码不参与该校验。

## 7.2 游戏管理

游戏编号按业务类型独立递增：游戏盒从 100001 起，快爆从 300001 起。

### 7.2.1 游戏列表

主要列：

- 游戏ID / 游戏名称
- 合同游戏名称
- 厂商ID / 厂商名称
- 已付游戏代理金
- 已付预付分成款
- 已付委托开发费
- 付款方
- 运营状态
- 操作

操作顺序固定为：

1. 编辑
2. 合同管理
3. 已付款项
4. 操作记录

列表规则：

1. 查询栏仅提供“游戏ID / 游戏名称”“厂商ID / 厂商名称”，两个条件使用 AND 关系；不提供“合同游戏名称”查询。
2. 付款方、运营状态支持表头筛选，并与顶部查询条件使用 AND 关系。
3. 默认按游戏添加时间倒序，新添加游戏置顶。
4. “付款方”位于“运营状态”左侧。
5. 三项已付款金额仅在合同勾选对应合作内容且已维护金额时显示，否则显示“-”；金额使用合同支付币种。
6. 列表最后一行显示“查询总计”，三个已付款金额在当前查询结果内按币种分别汇总。
7. 导出跟随列表权限，导出当前查询结果；文件包含除“操作”和“查询总计”外的列表字段，厂商ID、厂商名称拆成两列，金额展示口径与页面一致。
8. 添加游戏、编辑、合同管理、已付款项、操作记录分别受按钮权限控制。
9. 添加或编辑缺少必填项时，在字段下显示“{字段名}不能为空”并阻止保存；保存成功关闭抽屉并提示“提交成功”。
10. 操作记录列为操作人、操作时间、操作，按时间倒序；无记录时显示“暂无操作记录”。

### 7.2.2 添加游戏

| 字段 | 必填 | 规则 |
|------|------|------|
| 游戏名称 | 是 | 游戏正式中文名称 |
| 游戏英文名称 | 否 | 英文结算函使用 |
| 合同游戏名称 | 是 | 合同签约名称 |
| 归属厂商 | 是 | 支持按厂商ID或名称搜索 |
| 付款方 | 是 | 4399、纯游、游乐、游戏之家、香港4399、游家时代 |
| 游戏负责人 | 否 | 文本 |
| 版号 | 是 | 有 / 无 |
| 运营状态 | 是 | 未上线 / 已上线，默认未上线 |
| 备注 | 否 | 多行文本 |

添加游戏时，版号初始为“有”，运营状态初始为“未上线”；归属厂商只能从当前业务范围内厂商选择。

### 7.2.3 编辑游戏

1. 游戏ID只读。
2. 归属厂商只读。
3. 付款方只读，不允许在编辑时修改。
4. 其他字段沿用添加游戏规则。

### 7.2.4 游戏名称重名校验

1. 添加和编辑保存时均校验游戏名称是否重复。
2. 比较前去除名称首尾空格。
3. 与全部已有游戏名称做精确匹配。
4. 编辑时排除当前游戏自身。
5. 重名时阻止保存，并在游戏名称输入框下方显示“游戏名称已存在”。
6. 游戏英文名称在申请付款成功时冻结；英文结算函优先使用，未填写时回退冻结中文名称。
7. 付款方与【付款设置】中的“分成付款公司”是两个独立字段，不相互覆盖。

## 7.3 合同管理

| 字段 | 必填 | 规则 |
|------|------|------|
| 游戏ID / 游戏名称 | 否 | 只读 |
| 合同编号 | 是 | 文本 |
| 支付币种 | 是 | 人民币 / 美金；首次保存前可选，保存后锁定 |
| 合同金额 | 是 | 不小于0，两位小数 |
| 合作内容 | 是 | 游戏代理金、预付分成款、委托开发费；至少一项 |
| 游戏代理金 | 条件必填 | 勾选对应合作内容时显示 |
| 预付分成款 | 条件必填 | 勾选对应合作内容时显示 |
| 委托开发费 | 条件必填 | 勾选对应合作内容时显示 |
| 补充说明 | 否 | 多行文本 |
| 合作状态 | 是 | 合作中 / 合作终止；默认合作中 |

业务规则：

1. 三项合同约定金额使用合同支付币种。
2. 取消某项合作内容时，清空对应合同约定金额和对应已付款金额。
3. 保存合同变更后写入游戏操作记录。
4. 操作记录中的状态变更不显示标签：运营状态显示“变更运营状态：{最新状态}”，合作状态显示“变更合作状态：{最新状态}”。

## 7.4 已付款项

1. 入口位于游戏列表操作列“合同管理”之后。
2. 未维护合作内容时，不允许维护已付款项，并提示先维护合同信息。
3. 仅展示当前合同已勾选的合作内容。

| 字段 | 必填 | 规则 |

### 7.5.1 列表与入口

### 7.5.2 结算公式

自有渠道和外部渠道分别维护：

| 字段 | 必填 | 规则 |
|------|------|------|
| 扣税点 | 自动 | 默认跟随厂商发票；发票为“其他”时读取厂商管理中维护的扣税点 |
| 渠道费 | 是 | 0–100整数 |
| 分成 | 是 | 0–100整数 |

发票与扣税点映射：

| 发票信息 | 扣税点 |
|----------|--------|
| 增值税专用发票（6%） | 0% |
| 增值税专用发票（3%） | 3.36% |
| 增值税专用发票（1%） | 5.6% |
| 普通发票 | 6.72% |
| 其他 | 读取厂商管理维护值 |

结算公式口径：

`结算结果 = 金额基数 × (1 - 扣税点 - 渠道费) × 分成`

| 3 | 已选择“有”预付分成款，但未维护已付预付分成款 | 未补充预付分成款信息 |

### 7.10.4 申请付款确认

| 字段 | 必填 | 规则 |
|------|------|------|
| 汇率取值时间 | 是 | 日期选择器，精确至天，默认当天 |
| 汇率 | 是 | 正数小数，最多四位小数，失焦格式化为四位 |

1. 上月系统拉取收入或退款未完成结算时，弹窗显示风险提示，但允许继续申请。
2. 确认成功提示“申请付款成功，账户余额已清零”。
3. 游戏付款管理主列表最上方新增一条“未付款”记录。
4. 本次纳入的结算记录申请付款状态改为“已申请”。
5. 当前账户余额清零。
6. 申请成功时直接抵扣预付分成款，不等待标记付款：
   - 人民币合同：本次抵扣 = `min(待付款金额, 申请前剩余未抵扣分成款)`。
   - 美金合同：本次抵扣 = `min(待付款金额 ÷ 本次汇率, 申请前剩余未抵扣分成款)`。
   - 已抵扣分成款 = `min(预付分成款, 申请前已抵扣 + 本次抵扣)`。
   - 剩余未抵扣分成款 = `max(预付分成款 - 已抵扣分成款, 0)`。
7. 付款申请创建、结算记录改为已申请、账户余额清零和预付抵扣必须整体成功或整体失败；标记付款不得再次抵扣。

### 7.10.5 申请付款快照

确认成功时冻结：

| 分类 | 冻结内容 |
|------|----------|
| 游戏 | 游戏ID、游戏名称、游戏英文名称、合同支付币种 |
| 厂商 | 厂商ID、厂商名称、银行收款信息 |
| 预付 | 预付分成款、申请前已抵扣、申请前剩余、本次直接抵扣、抵扣后剩余 |
| 付款信息 | 付款币种、分成付款公司 |
| 时间与金额 | 申请时间、待付款金额、汇率取值时间、汇率 |
| 明细 | 本次纳入的已结算收入和退款记录 |
| 结算函 | 收入/退款明细、合计、汇率取值时间、汇率、抵扣、剩余和初始实际付款金额 |

快照规则：

1. 游戏付款主列表和查询读取最新游戏、厂商资料；修改主数据后，列表与查询同步变化。
2. 游戏付款管理后续金额换算优先使用申请时填写的冻结汇率。
3. 标记付款填写的实际付款值不反写结算函快照。
4. 结算函读取申请成功时冻结的游戏、英文名称、厂商银行信息、合同、预付、付款设置、汇率取值时间、汇率和金额，后续源资料变化不影响历史结算函。
5. 结算函汇率行显示为“汇率（汇率取值时间YYYY年MM月DD日）：0.0000”；日期和汇率均来自申请付款快照。
6. 结算函的本次抵扣与抵扣后剩余必须直接读取同一次申请付款快照，不得重新读取实时预付数据计算；申请前累计已抵扣包含历史已抵扣和历次申请抵扣。

### 7.11.2 标记付款

| 字段 | 必填 | 规则 |
|------|------|------|
| 游戏ID、游戏名称 | 否 | 只读 |
| 待付款金额 | 否 | 只读，人民币 |
| 实际付款金额 | 是 | 人民币，不小于0，两位小数 |
| 实际付款美金 | 否 | 美金，不小于0 |
| 分成付款公司 | 否 | 只读，取申请快照 |
| 收款信息 | 是 | 默认取申请时冻结的厂商银行信息 |
| 备注 | 否 | 多行文本 |

金额计算变量：

- `pending`：待付款金额
- `remaining`：申请时剩余未抵扣分成款
- `rate`：申请时填写并冻结的汇率
- `contractCurrency`：合同支付币种
- `paymentCurrency`：付款币种
- `net = max(pending - remaining, 0)`
- `usdNet = max(pending / rate - remaining, 0)`

初始金额：

| 情况 | 条件 | 实际付款金额（￥） | 实际付款美金（$） |
|------|------|-------------------|------------------|
| 1 | 预付分成款≤0 | pending | 付款币种为美金时为 pending/rate，否则为空 |
| 2 | 预付分成款>0且合同支付币种为人民币 | net | net/rate |
| 3 | 预付分成款>0且合同支付币种为美金 | usdNet×rate | usdNet |

用户可修改初始金额。点击“标记已付款”后保存实付、付款时间、收款信息和备注，并将状态改为“已付款”；结算函保持申请时快照不变。

## 7.12 结算函

### 7.12.1 基础规则

1. 结算函在申请付款成功时生成并冻结。
2. 付款状态变化及标记付款填写的实际金额不改变结算函。
3. 标题为“{厂商名称} 与 {分成付款公司对应公司全称} 合作分成结算确认函”。
4. 支持下载中文或英文PDF模拟文件。
5. 4399和纯游不支持英文下载，点击后提示“{分成付款公司}的分成付款公司不支持英文版结算函下载”。

### 7.12.2 英文游戏名称

1. 申请付款时冻结游戏英文名称。
2. 英文结算函优先使用冻结的游戏英文名称。
3. 申请时未填写英文名称时，回退使用同一申请快照中的中文游戏名称。
4. 申请成功后再修改游戏英文名称，不影响既有英文结算函。

### 7.12.3 明细与汇总

1. 收入明细按游戏和渠道分组，连续月份合并为一行。
2. 收入区包含合作产品名称、结算时间、游戏产品收入①、结算公式和结算金额。
3. 退款存在时展示退款区；无退款时整段隐藏。
4. `合计②`为收入结算金额合计。
5. `合计④`为结算退款合计。
6. `总计②-④ = 合计② - 合计④`。
7. 公式中的收入基数显示为①，退款基数显示为③。

### 7.12.4 预付抵扣

仅申请快照中剩余未抵扣分成款大于0时展示“结算/抵扣金额”和“剩余未抵扣预付分成款”。

支付币种为人民币：

- 当总计不小于剩余时，抵扣金额等于剩余，抵扣后剩余为0。
- 当总计小于剩余时，抵扣金额等于总计，抵扣后剩余等于剩余减总计。

支付币种为美金：

- 先按冻结汇率将总计折算为美金。
- 再按上述规则与美金口径的剩余未抵扣分成款比较。

### 7.12.5 实际付款金额

1. 始终展示。
2. 使用申请付款时按标记付款三种情况计算并冻结的金额。
3. 付款币种为人民币时使用`￥`，为美金时使用`$`。
4. 不使用标记付款后手工填写的实际付款金额。
5. 不展示“支付金额（大写）”。

## 7.13 收入汇总统计

### 7.13.1 查询维度

支持按游戏、渠道、厂商三个维度汇总。

| 维度 | 列 |
|------|----|
| 游戏 | 游戏ID / 游戏名称、合同已付款金额、总收入、累计实际付款金额 |
| 渠道 | 渠道、合同已付款金额（固定“-”）、总收入、累计实际付款金额（固定“-”） |
| 厂商 | 页面：厂商ID / 厂商名称、合同已付款金额、总收入、累计实际付款金额；导出：厂商ID、厂商名称仍为两列 |

页面不提供时间筛选，不展示时间列，也不按月份拆分；每个游戏、渠道或厂商汇总为一条截至当前的累计记录。

### 7.13.2 统计口径

| 指标 | 口径 |
|------|------|
| 合同已付款金额 | 游戏、厂商维度：已付游戏代理金 + 已付预付分成款 + 已付委托开发费，按币种分别展示；渠道维度固定显示“-”且不参与总计 |

| 累计实际付款金额 | 游戏、厂商维度累计全部已付款记录的实际付款金额；人民币；不包含申请付款时直接抵扣的预付分成款；渠道维度固定显示“-” |

渠道维度：

1. 系统拉取的收入和退款按汇总渠道“游戏盒 / 快爆”汇总。
2. 文件导入的收入仍按实际外部渠道名称汇总。
3. 列表、筛选、查询总计和导出使用相同渠道口径。
4. 渠道维度的合同已付款金额和累计实际付款金额在列表、查询总计和导出中均固定显示“-”。
5. 合同已付款金额是合同当前累计快照，不作为可按日期追溯的付款流水。

## 8. 状态与数据联动

### 8.1 结算记录状态

| 状态 | 说明 |
|------|------|
| 未结算 | 已导入或拉取，尚未执行结算 |
| 已结算、未申请 | 已产生结算收入或结算退款，可进入游戏账户余额 |
| 已申请 | 已纳入某次付款申请，不再重复计入可申请余额 |

### 8.2 付款记录状态

| 状态 | 可执行操作 |
|------|------------|
| 未付款 | 标记付款、结算函、请款凭证 |
| 已付款 | 详细信息、结算函、请款凭证 |

### 8.3 关键联动

1. 新增游戏后，结算配置管理自动出现该游戏。
2. 厂商发票信息变化时，跟随发票的扣税点同步变化。
3. 合同合作内容取消后，对应合同金额和已付款金额清空。
4. 已付款项变化后，游戏列表、游戏收入预付数据和收入汇总同步变化。
5. 结算完成后，游戏收入累计收入或累计退款同步变化。
6. 申请付款成功后，结算记录改为已申请，账户余额清零，付款列表新增记录。
7. 标记付款后，付款状态、付款时间和收入汇总中的累计实际付款金额同步变化。
8. 游戏付款主列表和查询使用最新游戏、厂商资料；结算函以申请时快照为准，避免历史函件随源数据变化。

## 9. 用户故事

1. 作为游戏运营人员，我希望维护厂商和游戏资料，以便财务结算能够关联正确主体。
2. 作为游戏运营人员，我希望维护合同合作内容、币种和已付款项，以便统计合同付款情况。
3. 作为财务人员，我希望按发票类型配置结算公式，以便自动计算结算收入和退款。
4. 作为财务人员，我希望维护每个游戏的自有渠道ID，以便从财务中心准确拉取数据。
5. 作为财务人员，我希望导入外部渠道收入并校验重复数据，以避免重复结算。
6. 作为财务人员，我希望拉取并结算收入和退款，以形成游戏可付款余额。
7. 作为财务人员，我希望维护预付分成和付款设置，以便正确计算抵扣和付款金额。
8. 作为财务人员，我希望付款申请时冻结汇率与业务资料，以保证后续付款和结算函口径一致。
9. 作为财务人员，我希望登记人民币和美金实付金额并上传凭证，以便完成付款留档。
10. 作为管理人员，我希望按游戏、渠道和厂商查看收入汇总，以便核对经营与付款情况。

## 11. 实现与测试关注点

1. 申请付款快照和结算函快照必须持久化；生成或查看结算函时不可用最新主数据覆盖。付款主列表与查询不受此限制，按最新游戏、厂商资料展示和匹配。
2. 新增的游戏英文名称快照字段应兼容历史付款记录；历史记录无该字段时回退中文名称。
3. 金额计算过程中建议统一使用最小货币精度或统一舍入方法，页面最终保留两位小数。
4. 汇率保存和计算最多使用四位小数，禁止使用标记付款时的临时输入覆盖申请快照汇率。
5. 自有渠道归类、拉取、列表、筛选、导出和统计必须使用同一“汇总渠道”映射。
6. 外部收入重复校验需要同时检查历史数据和同一批次数据。
7. 合同取消合作内容的清空操作需要同时覆盖约定金额、已付款金额及其下游展示。
8. 测试应覆盖人民币/美金、无预付/有预付、全额抵扣/部分抵扣、无退款/有退款、支持/不支持英文函等组合场景。
9. 权限校验必须同时落在菜单路由、按钮展示、查询接口、导出接口和写操作接口；业务范围过滤不能只依赖前端业务类型选择器。

## 12. 关键假设与开放问题

### 12.1 已采用的假设

1. 游戏名称重名范围为全部业务类型下的全部游戏，不仅限当前列表。
2. 游戏名称重名比较去除首尾空格，但区分其他字符差异。
3. 游戏英文名称选填，不作为申请付款前置条件；为空时英文函回退中文名称。
4. 历史付款记录若不存在新快照字段，允许读取可用的兼容回退值。
5. 原型中的文件上传、PDF下载和财务中心取数为交互模拟，正式开发需接入对应服务。
6. 已确认的权限运行规则为：业务未授权不隐藏功能入口但不返回数据；功能未授权隐藏入口；直接URL访问未授权功能显示“暂无权限”。

### 12.2 开放问题

1. 权限配置后台、角色与员工授权关系、默认角色模板、授权变更审计和审批流程需另行定义；业务范围与功能范围的运行规则已在本需求中确定。
2. 财务中心接口字段、错误码、重试与幂等协议需在接口设计阶段确认。
3. 外部报表的文件格式、工作表名称、字段类型和最大数据量需在导入接口设计阶段确认。
4. 英文结算函的正式模板、渠道英文名和付款方英文资料需由业务/法务最终确认。
5. 金额和汇率在服务端的精度、舍入模式及税务口径需由财务确认后固化。
