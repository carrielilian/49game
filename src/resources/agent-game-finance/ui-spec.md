## UI 基线与基础组件规范（最高优先级）

本节从当前可运行的「代理游戏台账」组件和交互中提炼，作为新增页面、重构页面及技术开发的统一 UI 基线。后续章节若存在旧名称、旧尺寸或旧交互，以本节和当前原型实现为准。

### 设计目标与适用范围

- 产品形态：桌面端财务管理后台，优先保证信息密度、金额可核对、操作路径明确。
- 默认视口：以桌面宽屏为主；内容不足时保持完整表头，内容超宽时由页面内容区承载滚动，不压缩关键金额和操作文案。
- 组件复用：优先使用 `components/` 下现有组件和 `agf-*` 样式，不在单个页面复制一套相似控件。
- 交互一致：同类查询、保存、结算、上传、状态反馈必须使用一致入口、状态和文案结构。
- 数据表达：ID 与名称、金额与币种、状态与时间均采用全平台统一格式；无值统一显示 `-`，空列表统一显示“暂无数据”。

### 页面骨架与空间体系

| 区域 | 规范 | 实现 |
|------|------|------|
| 整体布局 | 左侧固定导航 + 右侧顶部栏 + 内容区 | `AdminLayout`、`Sidebar` |
| 侧栏 | 宽 `220px`，深色背景 `#2C324E`；Logo 高 `48px` | `--sidebar-width`、`.agf-sidebar` |
| 顶部栏 | 高 `48px`，左右 padding `24px`，白底，下边框 | `.agf-header` |
| 内容区 | padding：上 `16px`、左右及下 `24px` | `.agf-content` |
| 页面卡片 | 白底、圆角 `4px`；列表统一横向 gutter `24px` | `.agf-card`、`--agf-gutter` |
| 基础间距 | 以 `4px` 为最小单位；常用 `8/12/16/20/24/32px` | 查询栏 gap `12px`、表单项间距 `20px` |
| 圆角 | 输入、按钮、表格、标签通常 `4px`；Modal `8px` | `style.css` |

页面层级顺序固定为：面包屑 → 页面卡片 → 查询栏/操作栏 → 主列表 → 分页。页面没有独立标题时，以面包屑当前项表达页面名称。

### 按钮规范

| 类型 | class | 使用场景 | 视觉 |
|------|-------|----------|------|
| 主按钮 | `agf-btn--primary` | 添加、保存、确认、导入、拉取、结算 | 主色底、白字 |
| 次按钮 | `agf-btn--default` | 取消、关闭、返回 | 白底、灰边 |
| 文字操作 | `agf-btn--link` | 表格操作列 | 无底色、主色文字 |
| 危险文字操作 | `agf-btn--danger-link` | 删除等不可逆操作 | 红色文字 |

- 所有常规按钮高度 `32px`、圆角 `4px`、字号 `13px`、水平 padding `16px`、图文间距 `6px`。
- 一个操作区只设一个明确主操作；弹窗/抽屉底部顺序固定为“取消”在左、主操作在右。【合同管理】【已付款项】【结算公式】【数据拉取】【付款设置】【请款凭证】抽屉的主按钮统一显示“确定”。
- 表格操作列使用文字按钮，按业务流程从左到右排列；不使用图标替代“编辑、结算、记录”等关键动作。
- 禁用态使用灰底、灰边、灰字和 `not-allowed`；禁用原因应可由当前页面状态或相邻说明理解。
- 异步按钮点击后立即进入处理中状态并防止重复提交；成功或失败后用 Toast 反馈。

### 查询栏与筛选规范

- `FilterBar` 第一行固定以业务类型开始，后接查询字段；字段间距 `12px`，控件高度统一 `32px`。
- 查询输入默认宽 `200px`；业务类型选择宽 `100px`；月份范围最小宽 `228px`。
- 同一输入框内允许 ID/名称“或”匹配，不同查询框和表头筛选之间使用“且”关系。
- 查询条件变更后即时刷新列表，不额外设置“查询”按钮；数据变化时 `DataTable` 自动回到第 1 页。
- 页面级主操作可通过 `actions` 放到第二行；导出等与查询紧密相关的操作可跟在查询字段后。
- 枚举筛选优先用 `ColumnFilter`；筛选菜单 Portal 到 `body`，不得被表格裁切；有筛选值时漏斗显示主色。
- 表头筛选选项第一项固定为“全部”，点击选项后立即生效并关闭菜单。

### 输入与表单规范

#### 通用输入

- 输入框、下拉框高度 `32px`，边框 `1px solid #E8E8E8`，圆角 `4px`；聚焦边框为主色。
- 页面查询控件字号 `13px`；抽屉表单字号 `14px`。
- 占位文案使用 `#999999`；只读值用纯文本，不伪装成禁用输入框。
- 文本域最小高度 `80px`，仅在确有多行内容时使用。
- 必填项在字段名前显示红色 `*`；必填与选填由业务规则决定，不在 placeholder 中重复说明。

#### 抽屉横向表单

- 标签固定宽 `168px`、右对齐，内容区自适应；标签后由样式统一生成中文冒号“：”。
- 表单项默认底间距 `20px`；标签和输入框左右布局，不使用同一抽屉内的上下布局。
- 区块标题使用 `FormSectionTitle`，区块间上边距 `24px`、下边距 `16px`。
- `FieldHint` 位于输入组件下方，错误发生时 `FieldError` 再显示在灰色说明下方。
- 校验错误既要定位到具体字段，也要显示页面级错误 Toast；字段输入发生变化时清除该字段旧错误。
- 金额输入失焦后统一格式化至两位小数；百分比按组件规则限制整数或最多两位小数。

#### 复合输入

| 组件 | 规则 |
|------|------|
| `CurrencyInput` | 左侧显示 `￥/$`；仅允许非负数字及最多两位小数 |
| `PercentAffixInput` | 右侧固定 `%` 后缀 |
| `DecimalPercentInput` | 数据存小数，界面显示百分数，范围 `0–100`，最多两位小数 |
| `PercentInput` | 数据存小数，界面输入 `0–100` 整数 |
| `ReadonlyCurrencyField` | 未维护时显示 `-`，已维护时显示币种符号和两位小数 |

复合输入的前后缀背景统一 `#F5F7FA`，前后缀与输入区共享同一聚焦边框。

### 表格与金额规范

- 主列表统一使用 `DataTable`；表格外框白底、灰色实线边框、圆角 `4px`。
- 表头不换行，背景 `#FAFAFA`，字号 `13px`、字重 `700`；单元格 padding `12px 16px`。
- 普通列左对齐；金额列使用 `COL_ALIGN_RIGHT`，表头和内容同时右对齐，并启用等宽数字。
- 游戏和厂商统一用 `DualCell` 显示为 `ID / 名称`；斜杠前后保留空格。
- 金额统一显示币种符号、千分位和两位小数；人民币用 `￥`，美金用 `$`。
- 多币种金额使用 `CurrencyStackCell` 上下排列，不在一个数字中混合币种。
- 主列表默认按数据添加时间倒序；新增、拉取、导入、申请生成的记录必须显示在最前面。
- 未结算、未填写或不适用的数据统一显示 `-`，不显示空字符串或虚假的 `0.00`。
- 空数据仍保留表头，表体显示空盒插画和“暂无数据”，分页显示“共 0 条”。
- 查询总计使用 `leadingRow` 或 `trailingRow`，固定行不参与分页；总计口径必须跟随当前筛选结果。

### 分页规范

- 默认 `20条/页`；允许 `10/20/30/50/100/200`。
- 分页位于表格外框下方并水平居中，依次展示总数、每页条数、上一页、页码、下一页。
- 数据条数或筛选结果变化后回到第 1 页；当前页超过最大页数时自动回退。
- 第一页禁用上一页，最后一页禁用下一页；页码过多时使用省略号。

### Modal、Drawer 与浮层

#### Modal

| 规格 | 宽度 | 使用场景 |
|------|------|----------|
| 默认 | 最大 `560px` | 普通确认、说明 |
| `compact` | `420–480px` | 简短确认、申请付款 |
| `large` | 最大 `720px` | 中等复杂内容 |
| `xl` | 最大 `960px` | 导入预览等宽表格 |

- 最大高度 `90vh`；只有日期下拉等必须溢出显示的场景使用 `overflowVisible`，避免弹窗内部产生不必要的上下滚动。
- 默认 header/footer 有分隔线；`plain` 用于轻量确认和导入等无分隔线布局。
- 点击遮罩、右上角关闭或按 `Esc` 均关闭；内容区点击不得冒泡关闭。

#### Drawer

- 默认从右侧进入，宽 `730px`、最大 `90vw`；特殊展示可通过 `width` 明确指定，不新增页面私有宽度 class。
- header 与 footer 固定，body 独立滚动；底部按钮右对齐。
- 编辑、详情、记录、配置等需要保留主列表上下文的操作优先使用 Drawer。
- 简短二次确认、文件导入和阻断提示优先使用 Modal。

#### 浮层关闭规则

- 日期、月份、筛选、搜索选择器点击组件外关闭。
- 选择明确选项或日期后立即关闭并生效。
- 保存失败时保持当前 Modal/Drawer 打开并保留用户输入；保存成功后按业务规则关闭并 Toast 反馈。

### 日期与月份组件

- `DatePicker` 输出 `YYYY-MM-DD`；默认日期由业务层传入，申请付款场景默认当天。
- 日历支持上一年、上一月、下一月、下一年；选中日期主色圆形高亮，非本月日期弱化。
- 弹窗中的日历向上展开且层级置顶，不能造成弹窗上下滚动或被底部裁切。
- `MonthRangePicker` 输出 `YYYY-MM - YYYY-MM`；第一次选择开始月，第二次选择结束月后关闭。
- 未来月份禁用；选中区间浅蓝连接，起止月份主色高亮。

### 上传组件

- 报表数据导入使用大面积虚线上传区；凭证附件使用 `MockFileUpload` 的“选择文件”按钮和文件列表。
- 上传区 hover 使用主色边框和文字；禁用时降低透明度并显示不可点击光标。
- 已上传文件显示文件图标、可点击文件名、成功图标和删除入口。
- 文件格式、大小、表头和数据内容校验按业务文档执行；校验失败不展示成功预览数据。
- 上传失败在上传区下方显示红色错误；成功后再进入预览或文件列表状态。

### 状态、反馈与校验

| 状态 | 表现 |
|------|------|
| 成功 | 绿色 Toast，显示 `3秒` |
| 失败 | 红色 Toast + 对应字段下红字，显示 `3秒` |
| 禁用 | 灰色按钮，不响应点击 |
| 处理中 | 按钮文案切换为“处理中...”类状态并禁止重复提交 |
| 空数据 | 表头保留 + “暂无数据”空状态 |
| 无权限 | 功能入口隐藏；URL 直接访问显示“暂无权限” |

- Toast 用于结果反馈，不替代字段错误；字段错误用于告诉用户具体修改位置。
- 多字段校验时一次扫描并展示全部字段错误，页面 Toast 统一提示“请完善所有信息”。
- 批量结算、批量导入等原子操作任一数据失败时不得部分落库。
- 删除、覆盖或其他不可逆动作必须有确认；普通取消和关闭不保存当前未提交内容。

### 状态标签

| 类型 | 适用状态 | 样式 |
|------|----------|------|
| success | 已上线、合作中、已申请、已付款 | 绿底绿边绿字 |
| warning | 未申请、未付款、待处理 | 橙底橙边橙字 |
| danger | 合作终止、失败 | 红底红边红字 |
| muted | 未上线、已下线、不可用 | 灰底灰边灰字 |

操作记录中的状态变化使用普通文本，例如“变更运营状态：合作中”，不使用状态标签，保证日志可复制和可审计。

### 权限与可访问性

- 业务未授权：菜单和页面入口保留，列表返回空数据。
- 功能未授权：对应菜单、页面入口或按钮隐藏，不展示禁用占位。
- URL 直接访问未授权功能：显示“暂无权限”，不加载业务数据。
- 可点击元素使用原生 `button/input/select`；纯图标按钮提供可读标签；弹窗和抽屉使用 `role="dialog"`。
- 颜色不能作为唯一状态信息，状态必须同时显示文字；金额、时间和错误信息必须可直接复制阅读。

### 新页面/新功能验收清单

- [ ] 页面使用统一 `AdminLayout`、面包屑、卡片和 `FilterBar`。
- [ ] 查询字段、表头筛选、列表结果和导出口径一致。
- [ ] 主列表使用 `DataTable`，金额右对齐，ID/名称合并规则一致。
- [ ] 新数据置顶，空值显示 `-`，空列表显示“暂无数据”。
- [ ] 表单为横向布局，必填、提示、错误顺序正确，保存失败保留输入。
- [ ] 主次按钮、禁用态、处理中状态和 Toast 符合统一规范。
- [ ] Modal/Drawer 尺寸与场景匹配，日期及下拉浮层不被裁切。
- [ ] 权限、批量原子性、重复提交和直接 URL 访问均有明确处理。
- [ ] 原型、标注、`ui-spec.md`、主规格和需求文档中的名称与口径同步。

| 属性 | 值 | 用途 |
|------|----|------|
| 渠道归属 | 自有渠道 / 外部渠道 | 相对当前业务类型判断 |
| 数据接入方式 | 系统拉取 / 文件导入 | 仅用于内部区分数据进入系统的方式；主列表不展示 |

- 游戏盒业务：游戏盒为自有渠道，快爆为外部渠道；快爆业务反向。
- 小米、荣耀、华为、爱九游、vivo、oppo、B站、TapTap、应用宝、ios、Steam 均为文件导入的外部渠道。
- 【数据拉取】抽屉顶部仅显示游戏和厂商，不显示业务类型及平台字段。
- 抽屉仅展示“自有渠道”“外部渠道”两个分组；标题及提示不展示数据接入方式、平台关系或角色信息。
- 文件导入的外部渠道不在【数据拉取】抽屉展示，通过【收入结算】的【数据导入】接入。

### 收入列表与结算

- 主列表不展示“数据来源”字段，也不提供对应表头筛选。
- 系统拉取：按“月 + 游戏ID + 汇总渠道”汇总；自有渠道取“待结算金额”，外部渠道取“结算收入”。
- 文件导入：接入文件导入的外部渠道收入，沿用“收入时间 + 渠道 + 游戏ID”判重与导入预览。
- 【收入结算】只要当前业务类型下存在未结算收入记录，【结算】即可点击，不依赖刚刚执行过拉取或导入，也不受月份、游戏、厂商、渠道和申请付款状态等查询条件影响。
- 收入：自有渠道使用自有渠道结算公式，所有外部渠道统一使用外部渠道结算公式。
- 退款：自有渠道使用本系统自有渠道结算公式，外部渠道使用本系统外部渠道结算公式；外部渠道的“退款金额”取财务中心“原始退款金额 × 财务中心结算公式”的结果。

### 整批原子规则

- 点击【结算】后先校验本次范围内的全部未结算记录，全部通过后才一次性写入。
- 任一记录失败，本批全部记录保持未结算，不更新结算结果、结算时间及下游账户。
- 缺少公式提示：`{游戏ID}缺少结算公式`；多个游戏ID去重后用中文顿号连接，例如 `100001、100002缺少结算公式`。
- 其他失败提示：`结算失败，本次数据均未结算：{原因}`。
- 退款结算沿用整批原子规则，并按实际渠道归属校验和使用本系统自有渠道或外部渠道结算公式。

### 权限展示规则

- 可操作数据 = 已授权业务范围 ∩ 已授权功能范围。
- 业务权限按“游戏盒、快爆”分别授权。业务未授权时不隐藏菜单、页面和已授权按钮；页面正常打开但不返回对应业务数据，使用常规“暂无数据”空状态。
- 功能权限按一级、二级、三级和按钮权限控制。未授权的菜单、页面入口或按钮直接隐藏，不展示禁用态。
- 通过URL、收藏或历史地址访问未授权功能页面时，不加载业务内容，统一显示“暂无权限”。
- 查询和导出跟随列表权限，不单独配置；查询结果和导出结果仍受业务权限约束。
- 结算函“信息查看”和“下载”分别控制：有查看权限但无下载权限时允许打开抽屉，但不显示下载入口。

**Modal 内口径**（`VendorIncomeFieldHelp`）：

1. 账户总收入 = 累计收入 - 累计退款  
2. 账户余额 = 收入结算「未申请」结算收入之和 − 退款结算「未申请」结算退款之和

**申请成功直接抵扣规则**：

- 人民币合同：本次抵扣 = `min(待付款金额, 申请前剩余未抵扣分成款)`。
- 美金合同：本次抵扣 = `min(待付款金额 ÷ 本次汇率, 申请前剩余未抵扣分成款)`。
- 已抵扣分成款 = `min(预付分成款, 申请前已抵扣 + 本次抵扣)`。
- 剩余未抵扣分成款 = `max(预付分成款 - 已抵扣分成款, 0)`。
- 未付款申请也已完成抵扣；标记付款不重复抵扣。申请创建、结算状态、账户余额和预付抵扣整体成功或整体失败。

**结果对照表（三种情况）**

| 情况 | 触发条件 | 实际付款金额（￥） | 实际付款美金（$） |
|:----:|---------|-------------------|------------------|
| 1 | 预付分成款 ≤ 0 | = 待付款金额 | 付款币种=美金时 = 待付÷汇率；否则空 |
| 2 | 预付分成款 > 0，合同支付币种 = 人民币 | = net | = net ÷ 汇率 |

6. **`汇率（汇率取值时间YYYY年MM月DD日）：`**（显示条件见「汇率行显示」；日期和汇率读取申请付款快照；汇率四位小数）

**汇率行显示**：付款币种为美金；或（支付币种（申请快照）为美金 且 申请付款时剩余 > 0）。剩余为申请时刻游戏收入列表「剩余未抵扣分成款」快照。

7. **（条件显示）** 仅当申请快照中「剩余未抵扣分成款」**> 0** 时，依次显示：
   - **`结算/抵扣金额：`**（原「本次抵扣预付分成⑤」，见下方⑤规则）  
   - **`剩余未抵扣预付分成款：`**（剩余 − ⑤）  
8. **`实际付款金额：`**（始终显示；取值见下方「实际付款金额」规则）  
9. 付款方开票信息、备注（左灰底标签右白底内容）；不显示“支付金额（大写）”

**付款币种**：游戏付款取 `Game.sharePaymentCurrency`；厂商付款取 `Vendor.sharePaymentCurrency`；默认人民币。

**实际付款金额**（游戏付款管理结算函）：

| 付款币种 | 取值 | 展示 |
|---------|------|------|
| 人民币 | **【申请付款】**时按三种情况算出并冻结（`letterSnapshot.letterPayAmount`） | **￥** |
| 美金 | 同上 | **$** |

> 与【标记付款】表单填写值无关；标记已付款**不**反写结算函实付。表单初始填充仍用 `resolveGameMarkPaymentDefaults`（每次打开重算）。

厂商付款管理仍用公式 `②−④−⑤`（无⑤时为 `②−④`）。

**结算函快照（游戏付款）**：【申请付款】成功时写入；打开只读，与付款状态无关。**标记已付款**不更新结算函（含「实际付款金额」）；表单实付仅写入付款记录。

结算函抵扣行必须直接使用申请付款时同一次计算生成的快照字段：申请前剩余取 `applySnapshot.remainingPrepayment`，本次抵扣取 `applySnapshot.prepaymentDeductionAmount`，抵扣后剩余取 `applySnapshot.remainingPrepaymentAfterApply`。其中申请前剩余已扣除历史已抵扣和历次申请抵扣；禁止结算函再次读取实时游戏数据独立计算。

**⑤ 取值**（均为【申请付款】时刻快照，写入结算函后不变）

| 项 | 说明 |
|----|------|
| 支付币种 | 申请付款那一刻的快照值 |
| 剩余未抵扣分成款 | 申请付款那一刻的快照值（与当时游戏收入列表一致） |
| 总计②−④ | 本函保存的合计 |

**支付币种 = 人民币**

| 条件 | 结算/抵扣金额（⑤） | 剩余未抵扣预付分成款 |

### 数据统计 — 收入汇总统计（`stats-summary`）

**查询栏**：查询维度下拉（游戏/渠道/厂商）+ `ListSearchFields`（`gameAndVendor`）；不提供时间筛选。

列表不展示时间列、不按月份拆分，按截至当前的累计口径随查询维度切换：

| 维度 | 列 |
|------|-----|
| 游戏 | 游戏ID / 游戏名称、**合同已付款金额**、总收入、**累计实际付款金额** |
| 渠道 | **渠道**（无筛选；系统拉取记录使用汇总渠道「游戏盒/快爆」，文件导入记录保留实际外部渠道）、**合同已付款金额**（固定 `-`）、总收入、**累计实际付款金额**（固定 `-`） |
| 厂商 | 厂商ID / 厂商名称、**合同已付款金额**、总收入、**累计实际付款金额** |

**合同已付款金额**：游戏、厂商维度 = 合同 **已付游戏代理金 + 已付预付分成款 + 已付委托开发费**，显示 **币种符号 + 千分位**；该指标为合同当前累计快照，不是按日期追溯的付款流水。渠道维度因合同付款无法归属具体渠道，固定显示 `-`。

**总收入** = 全部已结算的结算收入 − 全部已结算的结算退款。固定 **￥** + 千分位。

**累计实际付款金额** = **游戏付款管理**中状态为**已付款**记录的 **`actualAmount`（实际付款金额）** 全量累计；固定 **￥** + 千分位；不包含申请付款成功时直接抵扣的预付分成款。

| 维度 | 累加范围 |
|------|----------|
| 游戏 | 该 `gameId` 全部已付款 `actualAmount` 之和 |
| 厂商 | 该厂商下所有游戏全部已付款 `actualAmount` 之和 |
| 渠道 | 无法可靠归属渠道，固定显示 `-`，不参与查询总计 |

实现：`pages/RevenueSummaryPage.tsx`；切换维度时 `DataTable` 设 `key={dimension}` 重置分页。
