## 数据闭环约束

1. 每条“已申请”结算明细只属于一笔付款申请。
2. 付款申请待付款金额 = 所引用结算收入合计 − 所引用结算退款合计。
3. 申请成功时立即抵扣预付分成款，未付款和已付款记录均计入累计抵扣。
4. 结算函读取申请时冻结的明细、汇率和预付抵扣结果。
5. 未被付款申请引用的已结算明细进入游戏账户余额，可继续申请下一笔付款。
6. 未结算明细不进入账户余额和付款申请。
7. 所有主列表按数据添加时间倒序展示；新增、拉取、导入和申请生成的记录立即显示在最上方。
8. 已保存付款设置的预付游戏必须同时具备历史已抵扣、分成付款公司和付款币种；历史值为 0 时明确展示 `0.00`，不得用空值代替。
9. 已生成付款记录的游戏必须具有完整付款设置；100008 专门保留为未提交付款设置的申请拦截场景。
