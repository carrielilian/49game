# 申请付款

## 做什么

将当前游戏账户余额发起付款申请，写入游戏付款管理，并将相关结算记录改为「已申请」。

## 显示条件

仅当该行**账户余额 > 0** 时显示。

## 点击校验（红 Toast，不弹窗）

| 顺序 | 条件 | 提示 |
|------|------|------|
| 1 | 归属厂商五项必填银行信息未填全 | 未填写银行信息 |
| 2 | 未在【付款设置】选择是否有预付分成款，或未补充付款币种 | 请先配置【付款设置】，完善预付分成信息和付款币种信息 |
| 3 | 已选择“有”预付分成款，但【游戏管理 → 已付款项】未维护“已付预付分成款”（金额0视为已维护） | 未补充预付分成款信息 |

不再校验该游戏是否已有未付款记录。校验通过后弹出二次确认。

## 确认成功后的逻辑

在点击「确认申请」的**这一时刻**，系统按当时信息生成付款记录和结算函，并**固定保存**。之后即使游戏资料、预付分成、付款设置等发生变化，**本笔付款与结算函内容不变**（与是否已标记付款无关）。

### 当时固定保存的信息

| 分类 | 内容 |
|------|------|
| 游戏 | 游戏编号、游戏名称、游戏英文名称、**支付币种**（申请付款那一刻的快照值） |
| 厂商 | 厂商编号、厂商名称、银行收款信息 |
| 预付分成 | 预付分成款、申请前已抵扣、申请前剩余、本次直接抵扣、抵扣后剩余 |
| 付款信息 | **付款币种**、分成付款公司 |
| 时间与金额 | 申请时间、**待付款金额**（＝ 申请时账户余额）、汇率取值时间、汇率 |
| 结算明细 | 本次纳入的已结算收入/退款明细 |
| 结算函 | 整函内容（明细、合计、汇率、抵扣行、初始实际付款金额等） |

### 联动效果

| 页面/模块 | 发生什么 |
|-----------|----------|
| 游戏付款管理 | 主列表**最上方**新增一条「未付款」记录 |
| 内部/外部/退款结算 | 本次纳入的明细，申请付款状态改为「已申请」 |
| 游戏请款管理 | 该游戏账户余额清零（已申请明细不再计入余额） |
| 预付分成 | 申请成功时直接增加本次抵扣并扣减剩余；未付款状态也已经生效，标记付款不重复抵扣 |
| 结算函 | 随时打开均显示申请时保存的内容，不随后台数据变 |
| 标记付款 | 分成付款公司、收款信息、汇率及实付初始值均按申请时保存的信息展示（实付填写值写入付款记录，不反写结算函） |

标记已付款后，结算函**全部内容不变**。

### 申请成功时直接抵扣

- 人民币合同：本次抵扣 ＝ `min(待付款金额, 申请前剩余未抵扣分成款)`。
- 美金合同：本次抵扣 ＝ `min(待付款金额 ÷ 本次汇率, 申请前剩余未抵扣分成款)`。
- 已抵扣分成款 ＝ `min(预付分成款, 申请前已抵扣 + 本次抵扣)`。
- 剩余未抵扣分成款 ＝ `max(预付分成款 - 已抵扣分成款, 0)`。
- 创建申请、更新结算记录、账户余额清零和直接抵扣为同一次完整操作；任一步失败均不生效。
