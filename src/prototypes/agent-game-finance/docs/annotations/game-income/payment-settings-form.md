# 付款设置抽屉

## 区块一：预付分成信息

| 字段 | 规则 |
|------|------|
| 游戏ID / 游戏名称 | 只读；左边游戏 ID，右边游戏名称；打开抽屉时展示当前游戏 |
| 预付分成款 | 始终显示、只读；取【游戏管理 → 已付款项】的“已付预付分成款”（`Contract.paidPrepayment`）；币种取合同支付币种；未设置显示「-」 |
| 历史已抵扣分成款 * | 始终显示并必填；非负、精确至小数点后两位；填写数值需 ≤ 预付分成款－历史累计申请付款抵扣的预付分成款；无历史抵扣填写0 |

抽屉不显示“已抵扣分成款”和“剩余未抵扣分成款”；这两个值仍在列表及后续付款计算中使用。

## 区块二：付款信息

| 字段 | 规则 |
|------|------|
| 分成付款公司 * | 4399 / 纯游 / 纯游（美元） / 香港4399 / 游家时代。**初始**：未保存过为空（显示「请选择」）；已保存过显示已选项 |
| 付款币种 * | 人民币 / 美金单选。未保存时不默认选中任何币种；已保存过则显示已选项 |

## 按钮

| 按钮 | 行为 |
|------|------|
| 取消 | 关闭，不保存 |
| 确定 | 校验通过后保存历史已抵扣和付款信息并关闭；绿色「提交成功」 |

历史已抵扣分成款、分成付款公司和付款币种始终必填。历史已抵扣输入框下方分两行提示：“请填写线下已抵扣处理的预付分成款，若无则填写0；”“填写数值需 ≤ 预付分成款 - 历史累计申请付款抵扣的预付分成款。”超过上限时，字段下提示“历史已抵扣分成款需 ≤ {当前可填写上限}”，上限固定显示两位小数，例如“历史已抵扣分成款需 ≤ 2033.12”；其他校验失败显示对应字段错误并统一提示“请完善所有信息”。
