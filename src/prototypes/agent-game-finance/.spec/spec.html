Main Specification · Agent Game Finance

代理游戏财务平台主规格

本规格是当前原型的产品与验收基准，覆盖厂商、游戏、合同、结算配置、收入结算、付款申请、付款管理、结算函和收入汇总。 在规格确认前不得继续修改原型；确认后，原型与本规格需要保持双向同步。

规格状态：已确认 业务类型：游戏盒 / 快爆 原型：agent-game-finance 主规格：HTML
概览 信息架构 基础资料 结算配置 收入结算 付款流程 结算函 统计 验收 待确认

1. 规格概览

核心目标
收入到付款闭环

从基础资料、收入结算到付款申请和结算函留档。

关键原则
申请时冻结

付款申请和结算函读取申请成功时的快照，不随源数据漂移。

验收重点
口径一致

列表、导出、汇总、付款与结算函使用一致的数据规则。

1.1 目标用户

角色核心任务
游戏运营维护厂商、游戏、合同、合作内容和渠道游戏ID。
财务人员配置结算公式、导入/拉取收入数据、结算、申请付款、登记付款结果和凭证。
财务负责人查看付款记录、结算函和收入汇总，核对业务结果。
开发与测试按本规格实现并覆盖字段、流程、状态、异常、计算和快照验收。

1.2 范围边界

本次包含

  • 厂商、游戏、合同与已付款项
  • 结算配置与内部渠道
  • 外部收入、内部收入、内部退款
  • 游戏收入、付款设置、付款申请
  • 游戏付款、凭证、结算函、收入汇总

不在范围

  • 已移除的【厂商收入】、【厂商付款管理】
  • 角色权限、审批流、通知、会计总账
  • 真实财务中心接口、真实报表解析、正式PDF与文件存储
  • 日期版本规格与 spec-state.json
评审门禁：本规格确认前，不修改原型；确认后，任何功能、字段、文案、状态或口径调整必须同时更新原型和本规格。

3. 基础资料

3.1 厂商管理

区块字段规则
厂商信息厂商编号添加时“-”，保存后系统生成；编辑只读。
厂商信息厂商名称、发票信息必填 发票：专票6%、专票3%、专票1%、普通发票、其他。
厂商信息联系人、手机、邮箱、单位地址选填。
银行信息第一行开户名称、开户银行、开户银行所在地必填
银行信息第二行支行名称、银行卡号必填
银行信息第二行银行代码选填。
  • 编辑不可修改厂商编号和所属业务类型。
  • 发票变化后，结算配置中“跟随发票”的扣税点同步变化。

3.2 游戏管理

字段添加编辑规则
游戏ID系统生成只读不可人工修改。
游戏名称必填可编辑去除首尾空格后全局精确查重；重名提示“游戏名称已存在”。
游戏英文名称选填可编辑申请付款时冻结，英文结算函优先使用。
合同游戏名称必填可编辑合同签约名称，可与上线名称不同。
归属厂商必填可搜索只读支持厂商ID或名称搜索。
付款方必填只读4399、纯游、游乐、游戏之家、香港4399、游家时代。
版号、运营状态必填可编辑版号：有/无；状态：未上线/已上线。

游戏列表列序

游戏ID / 游戏名称 → 合同游戏名称 → 厂商ID → 厂商名称 → 已付游戏代理金 → 已付预付分成款 → 已付委托开发费 → 付款方 → 运营状态 → 操作。

  • 付款方位于运营状态左侧，保留表头筛选。
  • 操作顺序：编辑 → 合同管理 → 已付款项 → 操作记录。
  • 列表最后一行显示“查询总计”，三项已付按币种分别汇总。
  • 导出不含操作和总计行，字段顺序与列表一致。

3.3 合同管理与已付款项

模块字段/动作规则
合同管理合同编号、合同金额、合作状态必填 金额≥0，最多两位小数。
合同管理支付币种人民币/美金；首次保存前可选，保存后锁定。
合同管理合作内容至少一项：游戏代理金、预付分成款、委托开发费。
合同管理三项约定金额勾选对应合作内容后显示并必填。
已付款项三项已付金额仅显示合同已勾选项；必填、≥0、两位小数。
取消合作内容清空数据同时清空对应约定金额和已付款金额。

4. 结算配置管理

4.1 结算公式

内部渠道与外部渠道分别维护扣税点、渠道费和分成。

发票信息扣税点编辑规则
增值税专用发票（6%）0%跟随发票，只读。
增值税专用发票（3%）3.36%跟随发票，只读。
增值税专用发票（1%）5.6%跟随发票，只读。
普通发票6.72%跟随发票，只读。
其他手工填写百分数输入。

公式：结算结果 = 金额基数 × (1 - 扣税点 - 渠道费) × 分成

  • 渠道费、分成：0–100整数。
  • 抽屉内部小标题为“内部渠道”“外部渠道”。
  • 操作顺序：结算公式 → 内部渠道 → 操作记录。

4.2 内部渠道

业务类型代理渠道发行渠道
游戏盒 总类“游戏盒”：游戏盒付费、游戏盒内购、49广告联盟 总类“快爆”：快爆付费、快爆内购、快爆小游戏广告
快爆 总类“快爆”：快爆付费、快爆内购、快爆小游戏广告 总类“游戏盒”：游戏盒付费、游戏盒内购、49广告联盟
  • 总类使用黑色加粗文字，展示在具体渠道上方。
  • 勾选渠道后，渠道游戏ID必填。
  • 一个渠道支持多个游戏ID，使用英文半角逗号“,”分隔；保存时去除各游戏ID首尾空格，并过滤空段。

5. 收入与退款结算

5.1 外部收入结算

允许渠道：小米、荣耀、华为、爱九游、vivo、oppo、B站、TapTap、应用宝、ios。

阶段规则
数据导入字段：收入时间、渠道、游戏ID、游戏名称、厂商名称、待结算金额。
重复判断按“收入时间 + 渠道 + 游戏ID”检查历史和本批次。
重复提示单个：“{游戏ID}数据重复上传”；多个游戏ID用“、”连接。
成功预览第一行显示总计，仅汇总待结算金额。
确认导入写入主列表；结算收入、结算时间初始为“-”。
结算按游戏外部渠道公式计算，写入结算收入和结算时间。

5.2 内部收入结算

从【财务中心－结算管理－游戏收入结算】拉取，最终按月 + 游戏ID + 渠道总类汇总一条记录。

渠道类型渠道总类具体渠道取值字段
代理渠道当前业务平台付费、内购、广告渠道待结算金额
发行渠道另一平台付费、内购、广告渠道结算收入

5.3 内部退款结算

从【财务中心－结算管理－玩家退款记录】拉取，最终按月 + 游戏ID + 渠道总类汇总一条记录。

渠道类型取值规则主列表文案
代理渠道退款金额退款金额 / 结算退款
发行渠道退款金额 × 发行平台结算公式退款金额 / 结算退款

5.4 拉取按钮状态

  1. 每月首次进入：“数据拉取”可用，“结算”置灰。
  2. 财务中心仍有未结算数据：提示“财务中心还未结算完成”。
  3. 拉取成功：提示已拉取，“数据拉取”置灰，“结算”可用。
  4. 同月再次进入保持已拉取状态。

6. 游戏收入与付款

6.1 游戏收入列表

字段口径
账户余额当前可申请付款金额。
账户总收入累计收入 - 累计退款。
预付分成款取【游戏管理－已付款项】的已付预付分成款；不可修改。
已抵扣 / 剩余未抵扣预付未维护时显示“-”；币种为合同支付币种。
操作付款设置始终显示；余额 > 0 时显示申请付款。

6.2 付款设置

预付分成管理

  • 先选择“有无预付分成款”。
  • 选择“有”：显示只读预付分成款和必填历史已抵扣。
  • 选择“无”：隐藏两项并按预付0计算。
  • 抽屉不显示已抵扣和剩余未抵扣字段。

付费设置

  • 分成付款公司：4399、纯游、纯游（美元）、香港4399、游家时代。
  • 付款币种：人民币 / 美金；未保存默认人民币。
  • 不提供付款账号字段。

6.3 申请付款

前置校验顺序

  1. 厂商五项必填银行信息不完整 → “未填写银行信息”。
  2. 选择有预付但未维护已付预付分成款 → “{游戏名称}未补充预付分成款信息”。金额0视为已维护。

不再因该游戏存在未付款记录而拦截再次申请。

确认弹窗

字段规则
汇率取值时间必填 日期选择器，精确至天，默认当天；日历图层置顶且弹窗无上下滚动。
汇率必填 正数小数，最多四位，失焦格式化为四位。

申请成功联动

结算记录改“已申请”
→
游戏账户余额清零
→
付款列表首行新增“未付款”
→
保存付款与结算函快照

6.4 申请付款快照

分类冻结内容
游戏游戏ID、游戏名称、游戏英文名称、合同支付币种。
厂商厂商ID、厂商名称、银行收款信息。
预付预付分成款、剩余未抵扣预付分成款。
付费设置付款币种、分成付款公司。
时间与金额申请时间、待付款金额、汇率取值时间、汇率。
结算明细本次纳入的收入与退款。
结算函明细、合计、汇率、抵扣、剩余和初始实际付款金额。
快照原则：申请成功后，修改游戏、英文名、厂商银行、合同、预付或付款设置，不影响已申请记录。后续换算使用申请时填写并冻结的汇率。

6.5 游戏付款管理

主列表列：游戏信息、厂商ID、厂商名称、待付款金额、实际付款金额、实际付款美金、付款状态、申请/付款时间、操作。

功能规则
标记付款未付款可操作；实付人民币必填且≥0，实付美金选填；分成付款公司只读。
详细信息已付款可查看；金额、状态、付款方和收款信息只读，备注可编辑。
请款凭证结算函必填，发票选填；支持png、jpg、pdf。
结算函读取申请时快照；标记付款不反写。

标记付款初始金额

net = max(待付款金额 - 剩余未抵扣分成款, 0)
usdNet = max(待付款金额 / 冻结汇率 - 剩余未抵扣分成款, 0)

情况条件实际付款金额（￥）实际付款美金（$）
1预付≤0待付款金额付款币种为美金时：待付/汇率；否则空
2预付>0，合同人民币netnet/汇率
3预付>0，合同美金usdNet×汇率usdNet

7. 结算函

  • 申请付款成功时生成并冻结；付款状态及标记付款实付不改变结算函。
  • 收入区展示明细、合计②；存在退款时展示退款区和合计④；总计为②-④。
  • 申请快照中剩余未抵扣分成款>0时，显示结算/抵扣金额与抵扣后剩余。
  • 实际付款金额始终取申请时冻结值，不展示“支付金额（大写）”。
  • 英文版优先使用冻结游戏英文名称；未填时回退冻结中文名称。

8. 收入汇总统计

维度列特殊口径
游戏时间、游戏ID/名称、支付金额、总收入、结算付款金额按游戏聚合。
渠道时间、渠道、支付金额、总收入、结算付款金额内部按游戏盒/快爆总类；外部保留实际渠道。
厂商时间、厂商ID、厂商名称、支付金额、总收入、结算付款金额按厂商聚合。
  • 支付金额 = 已付游戏代理金 + 已付预付分成款 + 已付委托开发费，按币种分别展示。
  • 总收入 = 结算收入 - 结算退款，人民币。
  • 结算付款金额 = 已付款记录实际付款金额，按付款月份累加，人民币。
  • 列表、筛选、查询总计和导出使用相同口径。

9. 功能测试与验收清单

基础资料

  • 银行代码选填且位于银行信息第二行。
  • 游戏名称重名时提示并拦截，自身原名称可保存。
  • 编辑游戏时归属厂商、付款方只读。
  • 付款方列位于运营状态左侧，导出顺序一致。

合同与配置

  • 合作内容决定三项约定金额和已付款项显示。
  • 取消合作内容同时清空约定金额和已付金额。
  • 合同支付币种首次保存后锁定。
  • 发票税点映射及“其他”手输正确。

渠道与结算

  • 游戏盒/快爆的代理、发行渠道及总类映射正确。
  • 多渠道游戏ID使用英文半角逗号“,”分隔；保存后不存在首尾空格或空段。
  • 内部收入/退款按月+游戏ID+渠道总类汇总。
  • 外部导入同时检查历史与本批次重复。

付款设置与申请

  • 有/无预付控制字段显示与计算。
  • 银行信息、预付信息按规定顺序拦截。
  • 汇率日期默认当天，汇率最多四位小数。
  • 已有未付款记录不阻止再次申请。

快照与付款

  • 申请成功后余额、结算状态和付款列表联动。
  • 源资料变化不影响申请和结算函快照。
  • 后续计算使用申请时冻结汇率。
  • 全额抵扣允许实际付款金额为0.00。

结算函与统计

  • 英文函使用冻结英文名，空值回退冻结中文名。
  • 4399/纯游英文下载按规则拦截。
  • 无退款时整段退款区隐藏。
  • 统计列表、筛选、总计和导出口径一致。
