代理游戏财务平台主规格

本规格定义代理游戏财务平台的完整产品能力与验收基准，覆盖厂商、游戏、合同、结算配置、收入结算、付款申请、付款管理、结算函和收入汇总。 在规格确认前不得继续修改原型；确认后，原型与本规格需要保持双向同步。

核心目标
收入到付款闭环

3.1 厂商管理

用于建立当前业务类型下的签约厂商主数据。厂商资料是游戏归属、发票扣税点、申请付款前置校验、 结算函收款方信息和付款详情的基础来源。

查询、列表与权限

项目详细规则
业务范围按当前“游戏盒 / 快爆”业务类型展示；业务未授权时页面入口仍可见，但列表无数据。
查询单个“厂商ID / 厂商名称”输入框，ID或名称任一包含关键字即可命中；清空后恢复当前业务范围全部数据。
发票筛选列表“发票信息”表头支持按发票类型筛选；与厂商关键字使用AND关系。
默认排序按添加时间倒序；新添加厂商置顶。历史记录无添加时间时按厂商ID回退排序。
列表字段厂商ID / 厂商名称、发票信息、操作。
操作列表权限控制页面与查询；“添加厂商”“编辑”分别受按钮权限控制，未授权时直接隐藏。
空状态查询无结果或业务未授权时保留表头和分页区域，列表显示“暂无数据”。

添加/编辑厂商字段

区块字段必填控件与规则
厂商信息第一行厂商ID否添加时显示“-”；保存后由系统生成；编辑时只读，不允许人工修改。
厂商信息第一行厂商名称是文本输入，作为签约公司名称和全局厂商展示名称。
厂商信息第一行联系人、手机、邮箱否文本输入；系统不校验手机号或邮箱格式。
厂商信息第二行单位地址否文本输入；发票为“其他”时缩短占位，为扣税点留出同一行位置。
厂商信息第二行发票信息是下拉选择：增值税专用发票（6%）、增值税专用发票（3%）、增值税专用发票（1%）、普通发票、其他。
厂商信息第二行扣税点条件必填仅发票选择“其他”时在发票信息右侧显示；百分数0–100，最多两位小数，0视为有效；切换为其他发票类型时清空并隐藏。
银行信息第一行开户名称是文本输入；结算函“收款方”读取该字段。
银行信息第一行开户银行是文本输入，不使用银行下拉选项。
银行信息第一行开户银行所在地是文本输入，不使用省市级联选择。
银行信息第二行支行名称是文本输入。
银行信息第二行银行卡号是文本输入；按原值保存和展示，不在前端转换数值。
银行信息第二行银行代码否文本输入；结算函收款方信息中按保存值展示，未填写时显示空值。

保存、校验与跨页面影响

  • 厂商编号按业务类型独立递增：游戏盒从 4001 起，快爆从 8001 起。
  • 添加和编辑均校验厂商名称、发票信息及五项必填银行信息；发票为“其他”时再校验扣税点。
  • 单字段缺失时在对应输入框下显示“{字段名}不能为空”；存在任一错误时阻止保存，并显示红色“请完善所有信息”。
  • 编辑不可修改厂商ID和所属业务类型；取消或关闭抽屉时放弃未保存内容。
  • 添加厂商窗口底部主按钮显示“保存”，编辑厂商窗口底部主按钮显示“确定”。
  • 保存成功后关闭抽屉并提示绿色“提交成功”；新增记录立即置顶。
  • 发票变化后，结算配置中“跟随发票”的扣税点同步变化；发票为“其他”时读取厂商维护的扣税点。
  • 厂商名称变更后，各主列表和查询读取最新名称；已经申请成功的历史结算函继续读取申请快照，不随厂商资料变化。
  • 申请付款时校验五项必填银行信息：开户名称、开户银行、开户银行所在地、支行名称、银行卡号；任一缺失提示“未填写银行信息”。银行代码不参与该前置校验。

3.2 游戏管理

用于建立当前业务类型下的游戏主数据，并承载合同、约定金额、累计已付款项、状态变更和操作记录。 游戏编号按业务类型独立递增：游戏盒从 100001 起，快爆从 300001 起。

查询、列表、筛选与导出

项目详细规则
查询“游戏ID / 游戏名称”和“厂商ID / 厂商名称”两个输入框；两个条件使用AND关系，各输入框内部按ID或名称OR匹配；不提供“合同游戏名称”查询。
表头筛选付款方、运营状态支持下拉筛选，并与顶部查询条件使用AND关系。
默认排序按游戏添加时间倒序，新添加游戏置顶。
金额列仅当合同合作内容包含对应项目且已维护金额时显示；否则显示“-”；金额使用合同支付币种。
查询总计固定显示在列表最后一行，三项已付款金额分别按人民币和美金汇总；只统计当前业务权限及当前查询、筛选结果。
导出跟随列表权限；导出当前查询结果，不含“操作”和“查询总计”行；厂商ID、厂商名称拆成两列，金额和列顺序与页面口径一致。
权限添加游戏、编辑、合同管理、已付款项、操作记录分别受按钮权限控制，未授权入口直接隐藏。

添加/编辑游戏字段

字段必填添加编辑规则
游戏ID系统字段保存后生成只读不可人工修改。
游戏名称是可编辑可编辑游戏上线后的正式中文名称；保存时去除首尾空格后做重名校验。
游戏英文名称否可编辑可编辑申请付款成功时写入快照；英文结算函优先使用，未填则回退冻结的中文游戏名称。
合同游戏名称是可编辑可编辑签约合同使用的游戏名称，可与正式游戏名称不同。
归属厂商是可按厂商ID或名称搜索选择只读仅可选择当前业务范围内的厂商；保存后不可通过编辑游戏更换厂商。
付款方是下拉选择只读4399、纯游、游乐、游戏之家、香港4399、游家时代；该字段与付款设置中的“分成付款公司”相互独立。
游戏负责人否文本输入可编辑用于记录内部负责人。
版号是有/无，初始为“有”可编辑单选。
运营状态是未上线/已上线/已下线，初始为“未上线”可编辑变更后写入操作记录；已上线为绿色，未上线和已下线均为灰色；系统数据拉取仅处理已上线游戏。
备注否多行文本可编辑不参与查询、结算和付款计算。

游戏名称重名校验

  • 添加游戏窗口底部主按钮显示“保存”，编辑游戏窗口底部主按钮显示“确定”。
  • 添加和编辑保存时均校验；比较前去除输入值及已有名称的首尾空格。
  • 在系统全部游戏中按完整名称精确比较，不做模糊匹配；编辑时排除当前游戏自身。
  • 发现重名时阻止保存，并在“游戏名称”输入框下显示“游戏名称已存在”。

游戏列表列序、操作与记录

游戏ID / 游戏名称 → 合同游戏名称 → 厂商ID / 厂商名称 → 已付游戏代理金 → 已付预付分成款 → 已付委托开发费 → 付款方 → 运营状态 → 操作。

  • 操作顺序：编辑 → 合同管理 → 已付款项 → 操作记录。
  • 添加成功写入“添加游戏”记录；运营状态、合作状态、合同字段和已付款项变更均写入同一游戏的操作记录。
  • 操作记录列为操作人、操作时间、操作；无记录时显示“暂无操作记录”。
  • 操作记录中的状态变更使用纯文本：“变更运营状态：{最新状态}”“变更合作状态：{最新状态}”，不显示状态标签。
  • 添加或编辑缺少必填项时，在字段下显示“{字段名}不能为空”并阻止保存；保存成功关闭抽屉并显示绿色“提交成功”。
  • 游戏、厂商后续改名时，主列表读取最新资料；申请付款成功前不产生结算函快照。

3.3 合同管理与已付款项

两个功能均从游戏管理操作列进入，以当前游戏为唯一归属对象；抽屉顶部显示只读“游戏ID / 游戏名称”。

模块字段/动作必填详细规则
合同管理合同编号是文本输入，保存时清理首尾空格。
合同管理支付币种是人民币/美金；首次保存前可选，保存后锁定且只读。
合同管理合同金额是使用合同支付币种，金额≥0，最多两位小数，失焦后补齐两位。
合同管理合作内容是多选且至少一项：游戏代理金、预付分成款、委托开发费。已提交项目保持勾选并禁用，不可取消；本次新增但尚未提交的项目仍可取消。

6.3 申请付款

前置校验顺序

  1. 厂商五项必填银行信息不完整 → “未填写银行信息”。

预付分成款直接抵扣

  • 申请付款成功时立即抵扣，不等待标记付款，不使用占用或冻结后释放方案。
  • 人民币合同：本次抵扣 = min（待付款金额，申请前剩余未抵扣分成款）。
  • 美金合同：本次抵扣 = min（待付款金额 ÷ 本次汇率，申请前剩余未抵扣分成款）。
  • 已抵扣分成款 = min（预付分成款，申请前已抵扣 + 本次抵扣）。
  • 剩余未抵扣分成款 = max（预付分成款 - 已抵扣分成款，0）。
  • 结算函的本次抵扣与抵扣后剩余直接使用同一次申请付款快照；申请前剩余已包含历史已抵扣和历次申请抵扣，不再读取实时数据重新计算。
  • 申请创建、结算记录改为已申请、账户余额清零和预付抵扣必须整体成功或整体失败。
  • 标记付款仅记录实际付款，不再次抵扣预付分成款。

收入结算

场景前置条件与操作验收结果
数据拉取选择月份范围执行拉取。按“月＋游戏ID＋渠道总类”汇总；自有渠道取待结算金额，可拉取外部渠道取结算收入；重复拉取不产生重复记录。
无可拉取数据收入结算或退款结算执行数据拉取，但没有匹配记录。提示“暂无可拉取数据”；列表不新增记录，【数据拉取】保持可点击。
收入查询总计设置月份、游戏、厂商、渠道或申请付款状态查询条件，并切换分页。表头下首行汇总全部查询结果的待结算金额与结算收入，未结算结果按0计入；翻页后总计不变。
文件导入上传包含收入时间、渠道、游戏ID、游戏名称、厂商名称、待结算金额的文件。仅校验必要字段、游戏ID、渠道和金额；游戏名称、厂商名称及公式不参与导入校验；全部通过后显示预览和总计。
导入错误分别构造文件、表头、收入时间、游戏ID、渠道、金额及重复数据错误。按优先级校验；数据错误扫描全表并按行号汇总，页面只显示红色错误、不展示预览；重复提示“第n、m行数据存在重复内容”。
确认导入上传合法文件并点击确认导入。预览第一行汇总待结算金额；确认后数据写入同一收入主列表，主列表不区分或展示数据来源。
收入结算当前业务类型存在未结算收入记录，在任意查询条件下点击结算。查询条件不限制结算范围；系统校验当前业务类型下全部未结算收入的公式后整批计算，成功后写入结算收入和结算时间，已结算记录不重复结算。
整批失败批次中任一游戏缺少所需结算公式或记录校验失败。整批保持未结算，不允许部分成功；缺少公式按游戏ID去重并用“、”连接提示。

退款结算

场景前置条件与操作验收结果
数据拉取选择月份范围执行退款数据拉取。从财务中心玩家退款记录按“月＋游戏ID＋渠道总类”汇总进入主列表；代理来源取退款金额，外部发行来源先使用财务中心公式计算退款金额。
退款结算查询范围内存在未结算退款并点击结算。自有渠道使用本系统自有渠道公式、外部渠道使用本系统外部渠道公式计算结算退款；结果、公式和结算时间写入主列表。
退款查询总计设置月份、游戏、厂商、渠道或申请付款状态查询条件，并切换分页。表头下首行汇总全部查询结果的退款金额与结算退款，未结算结果按0计入；翻页后总计不变。
状态与失败重复结算或构造缺少公式、数据校验失败场景。已结算记录不重复处理；任一失败时整批退款保持未结算且不更新下游账户。

游戏请款管理

场景前置条件与操作验收结果
付款信息打开付款设置并填写历史已抵扣、付款公司和付款币种。预付分成款始终只读显示，取游戏管理已付款项，未维护时显示“-”；历史已抵扣、付款公司和付款币种均必填。
预付信息查看预付分成款并填写历史已抵扣金额。历史已抵扣金额非负、最多两位小数且不能大于“预付分成款－历史累计申请付款抵扣金额”；超限时红字显示当前可填写上限。
申请前校验分别构造银行资料不全、付款设置三项任一未填写、合同勾选预付但未维护已付预付金额。依次提示“未填写银行信息”“请先配置【付款设置】，完善付款信息”“未补充预付分成款信息”。
申请金额游戏存在已结算未申请收入/退款且账户余额大于0，点击申请付款。待付款金额等于本次纳入申请的已结算收入减已结算退款；已有未付款申请不阻止再次申请；弹窗不显示收入或退款未结算提醒。
汇率录入在申请弹窗选择日期并输入整数或小数汇率后移开焦点。汇率取值时间默认当天、精确至日且必填；汇率必须大于0、最多四位小数，失焦后统一显示四位小数，例如“7”显示为“7.0000”。
申请成功确认申请。账户余额立即扣减至本次申请后的值；纳入记录变为已申请；生成不可撤回的付款记录和申请快照。
预付抵扣分别使用人民币和美元付款币种连续申请多笔付款。人民币直接按待付与可抵扣余额较小值抵扣；美元先按申请汇率折算；剩余预付=预付分成款－历史已抵扣－累计本次抵扣，最低为0。

游戏付款管理

场景前置条件与操作验收结果
列表查询按游戏、厂商、付款状态查询付款记录。列表和查询读取最新游戏、厂商资料；付款金额、实际付款金额、实际付款美金及状态正确回显。
请款凭证上传结算函和可选发票后保存。结算函必填，发票选填；保存后附件可查看，缺少结算函不能提交。
标记付款对未付款记录填写实际付款信息并确认。记录更新为已付款并保存实际付款金额、实际付款美金和付款时间；全额预付抵扣允许实际付款为0。
详情查看打开已付款记录详情。展示申请、结算明细、预付抵扣、申请汇率、凭证及实际付款信息，金额可与来源记录核对。
结算函快照申请后修改游戏名称、英文名、厂商或银行资料，再打开历史结算函。付款列表显示最新资料，结算函仍使用申请时冻结的游戏、厂商、银行、付款方、币种、汇率及金额。
结算函展示分别打开有退款、无退款、人民币、美元及预付抵扣场景。有退款时显示退款区，无退款时隐藏整段；汇率行显示“汇率（汇率取值时间YYYY年MM月DD日）”；金额和剩余预付按冻结数据计算。
结算函下载选择中文或英文下载。中文按付款公司生成；英文使用冻结游戏英文名，空值回退中文名；4399和纯游不提供英文下载并显示提示。

收入汇总统计

场景前置条件与操作验收结果
维度切换依次选择游戏、厂商、付款方、渠道维度。每个维度对象只生成一条累计记录，不按月份拆分；页面不提供时间筛选和时间列。
统计指标核对总收入、累计退款、合同已付款金额、累计实际付款金额。总收入取已结算收入累计值，累计退款取已结算退款累计值；合同和付款指标与对应业务记录一致。
渠道维度切换至渠道维度查看游戏盒、快爆及第三方外部渠道。内部数据按渠道总类汇总；第三方保留实际渠道名称；渠道列无筛选；合同已付款和累计实际付款金额显示“-”。
总计与导出设置查询条件后核对列表、查询总计和导出文件。三者使用同一过滤范围与计算口径；页面合并字段在导出中按约定拆列。

权限与数据范围

场景权限条件验收结果
业务权限用户拥有页面功能权限，但无游戏盒或快爆业务授权。菜单、页面及已授权按钮仍显示；页面正常打开但无对应业务数据，列表显示“暂无数据”。
列表权限用户未获得某菜单的列表权限。菜单和页面入口隐藏；通过URL访问统一显示“暂无权限”，不加载业务数据。
按钮权限用户有列表权限但缺少新增、编辑、结算、申请、下载等按钮权限。仅隐藏未授权按钮，其他已授权功能可正常使用。
查询与导出用户拥有列表权限并设置查询条件。查询、总计和导出均只包含“业务授权范围∩当前查询条件”的数据。
服务端鉴权绕过前端直接请求未授权接口或提交越权业务数据。服务端拒绝请求，不返回、不创建也不修改越权数据。

9.3 关键状态与异常验收

对象状态或异常系统表现
收入结算记录未结算允许参与结算；查询条件只影响列表展示，结算按钮和处理范围按当前业务类型下全部未结算收入记录决定。
结算记录已结算、未申请计入游戏账户可申请余额，可被下一次申请付款纳入。
结算记录已申请不重复计入可申请余额，不允许再次被其他付款申请引用。
付款记录未付款允许维护请款凭证、查看/下载结算函及标记付款；主列表显示未付款状态。
付款记录已付款允许查看详细信息、请款凭证和结算函，不再显示标记付款。
预付分成无预付不展示预付金额和历史抵扣字段，所有申请按预付分成款0计算。
预付分成有预付且已用尽剩余未抵扣金额为0，后续申请不再产生预付抵扣。
收入导入存在任一校验错误不展示预览数据且确认导入不可用；修正文件并重新上传，全部通过后才进入预览。
批量结算存在任一失败记录全部记录保持原状态和原金额，下游账户、统计和申请余额均不更新。
金额计算结果出现负数账户余额、剩余预付等业务余额最低按0处理，不展示负余额。
